# Proposal-side validation card

- **Research question:** Does the morphology of a draft token proposal predict target disagreement in Korean speculative decoding on Wikipedia continuation and English→Korean FLORES translation?
- **Hypothesis:** A valid proposal classified as `CROSS_MORPHEME` has higher odds of rejection than `WITHIN_SPLIT`, after controlling for token frequency, draft/target entropy, proposal position, generation position, target-side fragmentation, and token/eojeol lengths.
- **Baseline / variant:** Refit the saved greedy-SD outcome model with the same prespecified controls, then add only the proposal-side morphology class. Existing target-side classes are retained for a separately labeled diagnostic model.
- **Primary metric:** Prompt-clustered adjusted odds ratio for proposal `CROSS_MORPHEME` versus `WITHIN_SPLIT` in the pooled P1+P2 data for each workload, with pair fixed effects; pair-specific estimates are replication checks.
- **Decision rule:** Confirm the effect for this Korean study only if the adjusted pooled OR is greater than 1 and its 95% CI excludes 1 on both Wiki and FLORES, while P1 and P2 point estimates are positive in both datasets. Otherwise report the direction/uncertainty without claiming confirmation.
- **Data / eligibility:** Existing 1,000-prompt Wiki run and all 1,012 FLORES devtest rows. Only proposals actually verified by target are outcomes: accepted proposals plus the first rejected proposal per block. Every suffix proposal after that rejection is excluded. P1/P2 are primary; historical Wiki P3 is sensitivity-only because its draft checkpoint revision is unresolved.
- **Measurement audit:** Accepted proposal IDs must exactly equal saved target IDs. For a first rejected proposal, the draft token must have an exact local tokenizer span and exact morphology-boundary alignment. Save complete-block and strict-prefix labels, whole-block round-trip flags, and invalid/ambiguous counts.
- **Budget / cheapest rung:** CPU-only trace reanalysis, no model weights or GPU; start with the completed 20-prompt-per-dataset P1 audit, then run all saved traces. Stop if trace/target joins fail or if full analysis exceeds four wall-clock hours.
- **Exploratory only:** Target-side-adjusted model, P3 Wikipedia estimates, context-label sensitivity, and any causal or runtime interpretation. This study tests conditional prediction/association, not a causal mechanism or speedup policy.
